Choose storage based on how long history must last and how many app replicas you need.

| Deployment                            | Storage            | Tradeoff                               |
| ------------------------------------- | ------------------ | -------------------------------------- |
| Evaluation or disposable instance     | Embedded memory    | History disappears on restart          |
| One app instance with durable history | Embedded disk      | Database remains tied to that instance |
| Multiple replicas or failover         | External SurrealDB | Requires a shared database you operate |

Every deployment needs [configured accounts and HTTPS ingress](/documentation/setup). Examples below use the `config.toml` and `secrets/` directory from that setup.

## Embedded memory

This is the default. Use it when history can be discarded:

```sh
docker run -p 127.0.0.1:8555:8555 \
  -v "$PWD/config.toml:/etc/celery-insights/config.toml:ro" \
  -v "$PWD/secrets:/run/secrets/insights:ro" \
  -e SURREALDB_STORAGE=memory \
  ghcr.io/danyi1212/celery-insights:latest
```

## Embedded disk

Mount a durable volume and configure a stable database root password in TOML:

```toml
[database.observation]
root_password_file = "/run/secrets/insights/database-root-password"
```

```sh
docker run -p 127.0.0.1:8555:8555 \
  -v "$PWD/config.toml:/etc/celery-insights/config.toml:ro" \
  -v "$PWD/secrets:/run/secrets/insights:ro" \
  -v celery-insights-data:/data \
  -e SURREALDB_STORAGE=rocksdb:///data/surreal \
  ghcr.io/danyi1212/celery-insights:latest
```

- `surrealkv:///data/surreal` is also supported.
- Keep one app replica. Separate local databases do not share history or leadership.
- Reuse the existing root credential when opening an existing database.

## External SurrealDB

All replicas use the same database, accounts and session secret:

```toml
[database.observation]
mode = "external"
url = "wss://surrealdb.example.com/rpc"
root_password_file = "/run/secrets/insights/database-root-password"
ingester_password_file = "/run/secrets/insights/database-ingester-password"

[ingestion]
leader_election.enabled = true
```

- Keep the database endpoint private. Its credentials are separate from application accounts.
- Verify root/bootstrap access before using a managed database service.
- Keep ingestion enabled on each replica so it can take over after leader failure.
- Replicas improve availability and web capacity; one elected ingester writes Celery events.

## Replicas that only serve reads

To exclude a replica from ingestion and leadership:

```toml
[ingestion]
enabled = false
```

Use this with the shared external database. These replicas cannot take over ingestion; other replicas must collect the events.
