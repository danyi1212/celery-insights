Configure storage, access and monitoring before running the app in production.

## Production checklist

- Prefer external SurrealDB before introducing multiple replicas, HPA, or rolling updates.
- Keep the app and workers on a network path that can reach the broker and result backend directly.
- Enable Celery task events on every worker pool you want represented in the UI.
- Configure stable database credentials, explicit application accounts and HTTPS ingress.

## Health, metrics, and scrape targets

- Use `/health` for liveness and readiness checks.
- Configure Prometheus `basic_auth` with an explicit account permitted to read metrics.
- Prometheus scrape targets are `/metrics`, `/metrics/verbose`, and `/metrics/system` depending on the level of detail you want.
- Verbose metrics add label cardinality, so scrape them less frequently than the core endpoint.

## Reverse proxy and TLS

- Bun serves the SPA, APIs, metrics and authorized observation reads. Direct `/surreal/*` access is denied.
- Set [`URL_PREFIX`](/documentation/configuration#url_prefix) for a shared path such as `/tools/celery/`; preserve that prefix in proxy forwarding and enable WebSocket upgrades.
- The built-in proxy is HTTP-only. Terminate TLS in your ingress, load balancer, or edge proxy.
- Configure explicit application accounts, serve HTTPS, and keep Bun and SurrealDB endpoints private behind ingress.

## Security defaults to override

- Use stable root credentials for persistent storage, and stable ingester credentials for external databases. See [database credentials](/documentation/configuration#database-credentials).
- Configure password accounts or OIDC with explicit role mappings in TOML, and a shared `authentication.session.secret` on every replica. Keep Bun/database listeners inaccessible outside the ingress; roll out every replica when credentials change.
- Store `BROKER_URL`, `RESULT_BACKEND`, and any config-file secrets in your secret manager rather than baking them into images.

## Incident capture and replay

- Use **Settings** -> **Download diagnostics** to capture a `debug bundle v2` while the issue is visible.
- Configuration credentials are always redacted. Task payloads and logs can still contain sensitive data.
- Replay the captured bundle with `DEBUG_BUNDLE_PATH` when you need an offline, read-only copy of the incident.
- If you work from this repository, `just start-debug /absolute/path/to/debug-bundle-v2.zip` is the quickest local replay path.
- Attach the redacted bundle to bug reports when possible, or share it privately if the issue requires sensitive context.

## Scaling semantics

- Extra replicas primarily improve availability and frontend capacity.
- Leader election prevents duplicate ingestion, so scaling replicas does not multiply event write throughput.
- Use external SurrealDB before introducing rolling updates, HPA, or multiple availability zones.
