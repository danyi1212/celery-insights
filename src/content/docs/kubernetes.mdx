Deploy Celery Insights on Kubernetes with the Helm chart. It connects to your existing Celery broker and result backend and installs a shared SurrealDB instance for task history.

## Install with Helm

Follow the [Helm installation guide](https://github.com/danyi1212/celery-insights/blob/main/charts/celery-insights/README.md#install):

1. Create a Secret containing your Celery connection details and authentication credentials.
2. Create `values.yaml` with your public HTTPS URL, ingress settings, and TLS Secret.
3. Install the chart, then open the dashboard and sign in.

The chart generates authentication configuration for an `admin` account. You do not need to write a configuration file for the first installation.

## Change the settings

Keep your changes in `values.yaml` and use that file for each Helm upgrade. For example, to run two Insights pods with a larger CPU request, add:

```yaml
replicaCount: 2
resources:
  requests:
    cpu: 500m
```

Both pods serve the dashboard and APIs. One elected pod collects Celery events, and another can take over if it fails.

Use `authentication` to change the Basic account or configure OIDC. For custom application settings, supply `config.toml`; you can also supply `config.python` for Celery configuration. The [configuration guide](https://github.com/danyi1212/celery-insights/blob/main/charts/celery-insights/README.md#configure-authentication-and-celery) explains these options and how to use existing ConfigMaps or Secrets.

## Keep history and scale

The default database is in memory, so replacing its pod loses history. Enable [persistent storage](https://github.com/danyi1212/celery-insights/blob/main/charts/celery-insights/README.md#keep-history-on-disk) before installing if you need history to survive restarts. You can also connect to an [external SurrealDB instance](https://github.com/danyi1212/celery-insights/blob/main/charts/celery-insights/README.md#use-an-external-database), including SurrealDB Cloud.

For automatic scaling, enable `autoscaling` and install Metrics Server. HPA scales Insights for web capacity and availability; event collection still runs on one leader. The database included in the chart stays a single instance. Use a separately managed database when you need advanced database scaling.

## Extend your deployment

The chart supports standard Kubernetes settings:

- Use `resources`, `nodeSelector`, `tolerations`, and `affinity` to control pod placement and resource allocation.
- Use `extraEnv` with Secret references for additional credentials.
- Use `extraVolumes` and `extraVolumeMounts` for certificates or other files.

See [chart values](https://github.com/danyi1212/celery-insights/blob/main/charts/celery-insights/values.yaml) for the available settings. Keep credentials in Secrets and use the same session key on every replica.

Chart-managed configuration changes restart the pods automatically. After editing an existing Secret or ConfigMap, restart the Insights Deployment to load the changes.
