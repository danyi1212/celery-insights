Use the [Celery Insights Helm chart](https://github.com/danyi1212/celery-insights/blob/main/charts/celery-insights/README.md#install) to deploy on Kubernetes. Follow its installation guide to create a credentials Secret, configure HTTPS ingress, and install the chart.

The chart connects to your existing Celery broker and result backend. By default, it installs an Insights Deployment and one private, shared in-memory SurrealDB instance. One elected Insights pod collects events; all replicas serve the dashboard and APIs.

## Configure your installation

Keep your Helm settings in `values.yaml` and pass that file when installing or upgrading. Start with the installation guide's HTTPS example, then add the options you need:

| Need                                           | Helm values                                            | Guide                                                                                                                                                           |
| ---------------------------------------------- | ------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| History that survives database restarts        | `surrealdb.surrealdb.path` and `surrealdb.persistence` | [Persistent storage](https://github.com/danyi1212/celery-insights/blob/main/charts/celery-insights/README.md#keep-history-on-disk)                              |
| Your own SurrealDB instance or SurrealDB Cloud | `surrealdb.enabled: false` and `database.externalUrl`  | [External database](https://github.com/danyi1212/celery-insights/blob/main/charts/celery-insights/README.md#use-an-external-database)                           |
| More Insights pods                             | `replicaCount` or `autoscaling`                        | [Replicas and CPU HPA](https://github.com/danyi1212/celery-insights/blob/main/charts/celery-insights/README.md#scale-insights)                                  |
| OIDC or custom application settings            | `authentication` and `config.toml`                     | [Authentication and configuration](https://github.com/danyi1212/celery-insights/blob/main/charts/celery-insights/README.md#configure-authentication-and-celery) |
| Existing Celery Python configuration           | `config.python` alongside `config.toml`                | [Configuration files](https://github.com/danyi1212/celery-insights/blob/main/charts/celery-insights/README.md#configure-authentication-and-celery)              |

The default database loses history when its pod is replaced. Choose persistent storage before installing if you need to retain it. Extra Insights pods improve web capacity and availability; they share one ingestion leader. Advanced database scaling belongs to an externally managed SurrealDB installation.

## Extend the chart

Use `resources`, `nodeSelector`, `tolerations`, `affinity`, and `podAnnotations` to fit your cluster. Use `extraEnv` with Secret references for additional credentials, and `extraVolumes`/`extraVolumeMounts` for certificates or configuration files. Keep credentials out of Helm values and ConfigMaps.

See [all chart values](https://github.com/danyi1212/celery-insights/blob/main/charts/celery-insights/values.yaml) for the available options. The chart's `surrealdb` section configures its official SurrealDB dependency; the included database supports one instance using memory or local disk.

Chart-managed configuration changes restart Insights automatically. After changing an existing Secret or ConfigMap, follow the [upgrade and maintenance instructions](https://github.com/danyi1212/celery-insights/blob/main/charts/celery-insights/README.md#upgrade-and-maintain). All replicas must share the same session key.

## When you need plain YAML

Render the chart for deployment systems that require Kubernetes YAML:

```sh
helm template insights oci://ghcr.io/danyi1212/charts/celery-insights \
  --version 0.1.0 --kube-version 1.35.0 --namespace celery-insights \
  -f values.yaml --skip-tests > manifests.yaml
```

Set `--kube-version` to your target cluster's version and review the rendered resources before deploying. Create the referenced Secrets separately. When deploying rendered YAML, your deployment system manages updates and resource cleanup instead of Helm.
