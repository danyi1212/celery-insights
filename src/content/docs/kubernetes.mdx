Install Celery Insights using the [official Helm chart source](https://github.com/danyi1212/celery-insights/tree/main/charts/celery-insights). The chart is currently a draft pending the configuration/authentication runtime and a matching image release; follow its README for development installation. It connects to your existing Celery cluster and does not install workers, a broker, or a result backend.

## Default topology

The chart runs one shared, private SurrealDB instance in memory. Insights pods connect to that Service instead of starting an embedded database per pod. Replacing an Insights pod preserves history; replacing the in-memory database loses it.

## Installation

Create the explicit connection/credential Secret shown in the [chart README](https://github.com/danyi1212/celery-insights/blob/main/charts/celery-insights/README.md), then install the chart using a tested image containing the Helm runtime changes. Access the ClusterIP Service through port-forwarding first; add ingress/TLS or a LoadBalancer when ready.

## Persistence and external databases

Enable a PVC and disk-backed datastore together to preserve observation history. Existing claims are supported without Helm taking ownership. Chart-created PVCs are retained on uninstall by default. Switching from memory to disk needs an explicit export/restore if you want to retain existing history.

For SurrealDB Cloud or a separately managed database, disable the bundled dependency and supply its endpoint and Secret-backed credentials. Advanced database scaling is managed outside this chart.

## Insights replicas and autoscaling

Insights APIs run on every replica, while leader election controls background ingestion and automatic cleanup. The chart defaults to one replica and offers optional CPU HPA. Install Metrics Server and configure requests/minimum/maximum replicas before enabling it. Scaling increases frontend/API capacity, not ingestion throughput.

The bundled database stays a single instance. Database upgrades use Recreate and interrupt access; Insights pods roll independently. Authentication requires durable identity/control storage even when observation history is disposable; see the chart's release prerequisites.

## Operational notes

Chart-managed file changes roll the Insights pods. Existing ConfigMaps/Secrets require an explicit rollout restart after updates. The public URL prefix must match the ingress path, and live WebSocket traffic must be forwarded. Core metrics describe shared history and should not be summed across replicas.

Use `/health` for process liveness and `/ready` for API responsiveness. These do not guarantee broker connectivity or ongoing ingestion. Helm rollback does not reverse database migrations; back up persistent storage before upgrades.
